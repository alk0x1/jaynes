Roles

A role is the method for a kind of work. Two come with Jaynes; you install the ones you write or your team shares.

small-change

A change of a few lines. The agent makes it in a copy of the project; Jaynes runs the project's whole suite in a box without internet, and the change must pass. Past 30 changed lines, or a file that runs outside any box, the run becomes high risk and asks you whether the change goes on; an agent may answer that for you, as a release.

fix-bug

  1. Jaynes finds how the project's tests run.
  2. A separate agent, which reads only your request and the project as it was, writes the cases the fix will be judged by. The fixer never sees them.
  3. An agent writes the smallest test that fails because of the bug, and Jaynes requires that it fail, printing the line quoted. You see the bug as plain examples. If no test shows it, the run stops with what the agent tried.
  4. An agent fixes the code, never the tests, until the bug's tests and the whole suite pass, and then the hidden cases. A case that fails sends the fix back with its sentence alone.
  5. The fix is merged into the branch you started from, never pushed; Undo on the run's page reverts it.

Installing roles

jaynes add https://github.com/alk0x1/jaynes#engine/roles/small-change
jaynes add ./my-roles/tidy      # a folder of yours
jaynes roles                    # what is installed
jaynes remove tidy

jaynes add takes a folder or a git address, with #path for a folder inside the repository. It installs a role only when it passes the conformance suite. jaynes update brings roles installed from git to their newest version. A run keeps its own copy of the role it started with, so changing a role never changes a run under way.

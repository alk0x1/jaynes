Runs and stops

What a run does with your project, what it costs, where it asks you, and what each answer does.

A run

A run takes the steps of its role in order, one at a time. Each step that works on the project gets its own copy: your repository at the commit it had, with the changes of the earlier steps it uses. Your working tree is never touched. At the end the run's changes are the branch jaynes/<run> in your repository; a role that delivers by merge also merges it into the branch you had checked out, only over a clean checkout and never pushing, and Undo reverts it.

An agent's step runs Claude Code with settings Jaynes writes from what the step may reach: which files it may change, whether it may run commands or read the web. Jaynes does not claim more than those settings give: Claude Code's sandbox covers its shell commands. What the agent asks beyond them comes to Jaynes: reading inside the project is granted by a rule, anything else is a question for you, which the agent waits for.

Checks

A step's output reaches the next step only after its checks pass.

  • An open check, such as the project's suite or the form of the output, is listed for the agent; when it fails, the reasons go back to the same session to be fixed in place, and no attempt is spent.
  • A hidden check, such as cases written from your request alone, is never shown to the agent; when it fails, the agent gets only its sentence, and the attempt is spent.
  • A fault of Jaynes or of the machine (a box that refuses, a program that does not start, a check that cannot judge) never spends an attempt: the run stops and says so.

Risk and cost

A run starts at low risk unless its role has a step that cannot be undone, or you raise it. Rules in code raise it when the change grows past 30 lines or 5 files, or touches a file that runs later outside any box (CI, hooks, package scripts, agents' settings); then the steps of the full path run too. Nothing lowers it. Every run has a ceiling, said when it starts: 20 minutes and 2 million tokens at low risk, 2 hours and 10 million at high. No attempt starts past it; you can raise it on the run's page.

Your answers

A question shows items, and you give each a verdict; an item you leave unmarked is kept.

VerdictWhat it does
KeepThe item stays as it is: no later round of the step may change it
ChangeThe step runs again to change it as you wrote
RedoThe step does it again, with your note
DropThe item does not come back in the run
I don't knowIt stays as it was made, and is not judged

The line of context changes no verdict: your words go to the agents that work after the answer. When an answer sends a step back, that step runs again on top of what it made, and the steps that used it run again only if it comes out different. Before you send, the page says what the answer will do; Jaynes does what it said.

A run does not wait at a stop unless the role says so; it goes on and delivers, and the run finishes once you have answered. A step that cannot be undone waits for every answer it rests on.

What an agent may answer

Only you answer questions of taste or direction. At a stop the role marks as a release, such as small-change's "this turned out bigger than a small change", an agent may let the result go on as it is; that counts as the agent's, locks nothing, and nothing that cannot be undone rests on it.

Stops that ask less

A stop with an error budget asks only one run in ten once its record proves, by a test that holds however often it is checked, that its error rate is below the budget. What counts is what happened after delivery: an accept counts as right only after its delivery held 7 days, and a send-back or a correction counts as an error at once. Two errors among its last ten outcomes make it ask on every run and hold the run again.

The record

Everything a run does is an entry in a record in ~/.jaynes/engine, each chained to the one before by its fingerprint, so a change to any past entry shows (jaynes verify), and no run goes on over a record that does not hold. After a crash, the next process stops what the dead one left running and goes on; an attempt cut short is not counted against the agent. A run stays on the version of its role and of the engine it started with.

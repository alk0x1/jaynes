Write a role

A role is a program of its own, in any language, that speaks a fixed protocol with the engine. The engine owns the order of the steps and what each answer does; the role says what its steps are, writes the agent's instructions, does its own steps and judges outputs.

In Python

A role is a folder with a role.py. The library comes with Jaynes, written next to its record, and so does jaynes_box, which finds how a project's tests run and runs a project's commands in a box.

from jaynes_role import Fail, Pass, Role, Stop

role = Role("tidy", version="1.0.0")
role.step("tidy", executor="agent", reach={"project": "write", "write": ["**"], "commands": True},
          stop=Stop(verdicts=["keep", "redo"]), instructions="Tidy the module the request names.",
          schema={"type": "object", "required": ["summary"]})

@role.check("tidy", "summary", about="the output says what changed")
def summary(call):
    return Pass() if call["output"].get("summary") else Fail("say what changed")

if __name__ == "__main__":
    role.serve()

jaynes conformance ./tidy checks it; jaynes add ./tidy installs it.

Steps

executoragent (Claude Code does it), role (the role's own function, run=, for evidence an agent could fake) or person (a question over the steps it needs)
needsEarlier steps whose outputs it reads
reachproject: none, read or write; write: the paths it may change (! keeps some out); network: web; commands

Checks and items

@role.check(step, name, kind="open"|"hidden", about=..., reads=[...]) judges a step's output and returns Pass(), Fail(*reasons, detail=...) or Blocked(reason) when it cannot judge. The reasons go to the agent; the detail only to you. A hidden check may read a hidden step, such as the cases a proof runs.

@role.items(step) lists what you are shown of an output: {"id", "label", "content", "detail", "pictures"}, pictures being image files in the step's copy of the project. Without it the whole output is one item.

Role(name, version, delivery="merge") makes the run merge its delivery into your branch.

The protocol

For each call, the engine starts the role's program, writes one request as a line of JSON and reads one reply: hello, describe, prompt, execute, check and items. Any language that does that is a role; the schema is role-protocol-1.schema.json, and the conformance suite says whether a role answers it as it should.
